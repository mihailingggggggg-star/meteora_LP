# 02 · Phantom: вход по паролю + привязка кошелька (проверено по docs.phantom.com)

## Главное открытие, которое меняет план

> **Phantom Portal не принимает новые приложения.** Дословно из доков:
> *«Phantom Portal is not accepting new applications at this time. New sign-ups for Phantom Connect SDK access and new app submissions to the Phantom app directory are paused. Existing Portal apps and App IDs are not affected.»*

Что это значит на практике:

| Возможность | Нужен `App ID` (Portal) | Доступно нам |
|---|---|---|
| Embedded-кошелёк Phantom (вход через Google/Apple, кошелёк «внутри» приложения) | **Да** | ❌ нет (Portal закрыт) |
| React Native SDK | **Да** (всегда) | ❌ нет |
| Подключение **расширения** Phantom через `window.phantom.solana` | **Нет** | ✅ да |
| Phantom Connect SDK в режиме `injected` (только расширение) | **Нет** | ✅ да |
| Deeplinks `https://phantom.com/ul/v1/connect` (открыть Phantom на телефоне) | **Нет** (`dapp_encryption_public_key` + `app_url`) | ✅ да, со своими шифр-сессиями |
| Попасть в каталог Phantom / красивый брендинг в окне подключения | Да (+ DNS-верификация домена) | ❌ сейчас нельзя |

**Вывод:** «войти в кошелёк через интерфейс по паролю» и «подвязать интерфейс как приложение» делаем **без Phantom Connect**:

1. **Свой вход** — email/логин + пароль (Argon2id) + опционально TOTP, сессия в `HttpOnly` cookie. На телефоне — Face ID/Touch ID (WebAuthn/passkey) как быстрый повторный вход.
2. **Привязка Phantom** — пользователь нажимает «Подключить Phantom» → стандартное подключение (расширение на ПК; на телефоне — deeplink в приложение Phantom) → подпись сообщения **SIWS** (Sign-In With Solana) → сервер проверяет подпись (`tweetnacl` + `bs58`) и привязывает адрес к аккаунту. Это и есть «интерфейс привязан к кошельку»: адрес подтверждён криптографически, а в самом Phantom наш домен отображается как dApp.
3. **Мобильное приложение = PWA** (иконка на рабочий стол, полноэкранный режим). Это ещё и единственный путь: React Native SDK без App ID невозможен.

Важные технические детали SIWS (из доков):
- `domain` в сообщении должен **точно** совпадать с хостом страницы (включая порт: `localhost:3000`), `uri` — совпадать по origin. Иначе Phantom вернёт `-32000 Invalid Input` без показа окна.
- Подпись проверяем на сервере: `nacl.sign.detached.verify`. Nonce одноразовый, TTL 5 минут, привязка к сессии.

## Как бот торгует 24/7, если Phantom умеет подписывать только вручную

Это ключевой архитектурный выбор, его надо подтвердить (см. вопрос №2 в `05-KEYS-AND-ACCESS.md`).

**Факт:** Phantom (расширение/deeplink) подписывает только по нажатию человека. Серверного/делегированного подписанта у Phantom нет. Значит:

- **Модель A (рекомендую) — отдельный торговый кошелёк («hot wallet»)**
  - Создаём отдельный кошелёк Solana под торговлю. Его приватный ключ хранится **только локально**, зашифрован AES-256-GCM (ключ шифрования — в `.env`/Keychain, в репозиторий не попадает).
  - Вы пополняете его с Phantom (перевод SOL) — на нём только торговая сумма, «на жизнь» там ничего нет.
  - Phantom используется для: входа/подтверждения владельца, вывода средств, ручной аварийной остановки.
  - Любой вывод и любое изменение риск-лимитов требует подписи Phantom (SIWS) + пароля.
  - Плюс: работает 24/7 без вас. Минус: ключ на машине — риск при компромате машины; лечится лимитами, отдельным кошельком и Cloudflare Access на интерфейсе.
- **Модель B — каждую сделку подтверждаете в Phantom.** Максимальная безопасность, но бот не может работать без вас → нарушает «24/7, 15–18 ч в сделке». Не подходит.
- **Модель C — «сессионные ключи»** (как ERC-7715 у EVM). В Phantom для Solana такого публичного механизма нет.

## Схема авторизации (что реализуем)

```
[ПК]  Браузер ──пароль──► Next.js (auth) ──► cookie-сессия
      Браузер ──window.phantom.solana.connect()──► адрес
      Браузер ──signMessage(SIWS)──► сервер: verify ──► привязанный адрес

[PWA] Safari/Chrome ──пароль/Face ID──► cookie-сессия
      «Подключить Phantom» ──deeplink──► приложение Phantom ──signMessage──► redirect назад
      ──► сервер: verify ──► адрес привязан

Оба контура ──► Cloudflare Access (email OTP) ──► туннель ──► localhost
```

Уровни защиты:
1. **Cloudflare Access** (Zero Trust, бесплатно до 50 пользователей) — внешний пароль/OTP на весь интерфейс, до того как запрос дойдёт до вашей машины.
2. **Свой логин** — Argon2id + TOTP (опционально) + лимит попыток + блокировка.
3. **Подтверждение критичных действий** — SIWS-подпись (вывод, смена режима demo→live, снятие позиции).
4. **Изоляция движка** — слушает `127.0.0.1:8787`, наружу не смотрит; всё через Next.js-прокси с проверкой сессии.
5. **Аудит** — каждое действие (вход, подключение кошелька, сделка, вывод) в журнал.

## Что нужно от вас по Phantom

- Приложение **Phantom** установлено (расширение в браузере + приложение на телефоне).
- Кошелёк, с которого вы пополните торговый кошелёк.
- Понимание/согласие с **Моделью A** (иначе 24/7 невозможен).
- Если у вас **уже есть** действующий Phantom Portal App ID (например, от другого проекта) — скажите: тогда можно добавить embedded-кошелёк и красивый брендинг в окне подключения. Новый получить нельзя.
